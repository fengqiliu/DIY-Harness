# 代码评审

从用户会使用的入口追踪至改动位置，核对行为是否满足验收场景。查看相关调用方、原有数据约定和测试，尤其关注正常路径通过后仍可能出错的分支，例如重复提交、部分写入或异常后的状态。

对每个需要修正的问题，记录文件和位置、可达的触发条件、可以观察到的影响，以及可验证修复的场景。推测项标出缺失的证据。按影响排序，优先呈现会阻碍交付的问题。

发现影响验收的问题时，将对应场景、改动位置和复查条件退回实现角色。次要建议单独标记，说明是否影响当前验收。评审通过时列出看过的入口、差异范围和仍需运行验证的部分。
