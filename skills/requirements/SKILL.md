# 需求与复现

从用户描述中找出谁在什么入口做什么，以及操作结束后谁能观察到什么变化。用现有入口、接口契约或已有用例补齐背景，并注明仍需确认的假设。

处理功能需求时，把关键场景写成「给定前置条件，执行操作，应观察到结果」。当空数据、历史数据或权限差异会改变结果时，给出对应例子。写清本次涉及哪些入口，以便设计方判断改动边界。

处理缺陷时，用可共享的最小输入记录版本、入口、操作、期望和实际结果。保留失败断言、返回值或可定位的日志。复现受环境限制时，区分亲自观察与用户报告，写明还缺哪项条件。

交接一份场景清单。每个场景给出可复用的输入和通过标准，涉及取舍的假设单列，方便后续逐项验证。
