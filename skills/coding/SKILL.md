# 实现与修复

先阅读目标仓库的适用规则、工作区差异和受影响的实际入口。围绕验收场景定位业务规则的所有者，优先沿现有调用链修改。

修复缺陷时，尽可能先用最小输入观察旧行为，再用相同输入验证修复。若原环境暂不可用，保存可独立检验的部分和复现限制。涉及持久化、重试或旧格式时，确认已有数据经过新逻辑后的结果。

选择能区分新旧行为的最小检查。现有测试已经覆盖的场景可直接复用；只有具体回归缺少覆盖时再补用例。检查最终差异，保留他人已有的修改。

交接改动入口、对应场景、执行过的命令和观察结果。把暂缺的环境或数据条件列在受影响的场景旁。
