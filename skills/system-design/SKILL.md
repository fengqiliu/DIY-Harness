# 系统设计

沿一个真实入口定位调用方、业务规则和状态所有者。在设计中引用相关代码路径或契约，说明哪一层应负责变化，以及哪些调用方依赖它。

描述一次成功操作如何改变状态。涉及写入或对外接口时，追踪中途失败后的可见结果、调用方重试，以及旧版本调用方或已有数据的表现。只展开本次变更确实触及的约束。

把验收场景映射到改动位置和验证入口。只有存在会改变成本或行为的取舍时，才记录备选方案及选择理由。

交接时给出改动顺序、需保持的契约、验收入口和仍待验证的假设。接手人应能从这些位置找到第一处改动，并判断失败时应保留什么状态。
